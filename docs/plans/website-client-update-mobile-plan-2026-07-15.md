# 官网客户端下载与移动端计划

## 本轮目标

- 官网不再使用固定的 OSS 客户端直链。
- 首页和下载区统一读取 `GET /api/client-update` 返回的最新地址与版本号。
- 下载清单不可用时，不回退到旧地址，明确提示用户稍后重试。
- 修正当前手机端最影响操作的布局与入口问题。

## 已评估结论

在 390 x 844 手机视口下，首页可正常打开，没有发现横向溢出；游戏列表与下载区已具备单列布局。

需要处理的项目：

1. 首页和下载区仍固定指向旧 OSS 地址，且下载区显示硬编码 `v2.0.0`，与线上更新服务的 `1.2.6` 不一致。
2. Hero 在手机端最小高度为 640px，首屏信息密度偏低；搜索按钮采用绝对定位，后续内容变化时有挤压风险。
3. 手机菜单包含管理后台入口，对普通访问者没有价值，且会分散主导航的注意力。
4. `GameGrid` 只在首次渲染时判断屏幕宽度，横竖屏切换后“加载更多”的数量不会跟随更新。这是低优先级体验问题。

## 本轮范围

- P0：新增共享的更新清单请求 Hook，缓存同一页面的请求结果。
- P0：首页 Hero 与下载 CTA 使用清单内的 HTTPS 安装包地址和版本号。
- P0：清单请求失败时禁用下载操作并展示明确状态，不保留旧链接。
- P1：手机端压缩 Hero 首屏；搜索框改为弹性布局；主要操作按钮在窄屏下占满一行。
- P1：从手机导航移除管理后台入口，桌面端入口保持不变。

## 手工验收

1. 打开首页，检查 Hero 和底部下载区均显示更新服务返回的版本，点击后跳转到对应安装包域名。
2. 断开网络或将更新接口暂时模拟为失败，确认页面不会跳转到旧 OSS 地址，并显示“下载暂不可用”。
3. 在 390px、768px、1440px 宽度下检查首页：导航、搜索、两个主操作按钮和下载区均无横向滚动或按钮遮挡。
4. 在手机宽度打开菜单，确认仅保留首页和游戏库。
5. 执行 `npm run build`，确认 TypeScript 与 Vite 构建均通过。

本地 Vite 地址不在生产 API 的 CORS 白名单中，不能用 `127.0.0.1` 直接验证线上清单加载；应以生产官网来源的 CORS 响应和部署后的手工测试为准，或在本地启动 API 服务并将本地来源加入仅开发环境的 `CORS_ORIGIN`。

## 回滚边界

- 本轮前端改动仅涉及下载链接读取、手机端布局和导航展示；恢复到上一前端提交即可回滚，不影响 API 服务和已存在的更新清单。
- 不删除现有的 `client-update.json`、`server.js`、`README.md` 或环境变量示例改动；这些属于本轮开始前已存在的服务端工作区改动。

## 后续任务

### P1：下载与转化

- 在下载区展示更新说明和发布时间，帮助用户判断是否为最新客户端。
- 为客户端下载安装提供 SHA-256 校验说明和常见安装问题入口。
- 在游戏详情页为手机端增加底部粘性操作条，将下载、攻略和爆率查询保持在拇指可达区域。

### P2：移动端体验

- 将 `GameGrid` 的加载数量改为响应式状态，支持横竖屏切换。
- 为移动端搜索结果和游戏详情补充空状态、返回顶部与更清晰的筛选反馈。
- 对触屏设备减少仅靠 hover 才能发现的卡片信息，确保关键信息默认可见。

### P2：运营与安全

- 将公告、Banner、客户端更新说明整理为后台可运营的内容，并增加预览校验。
- 下载服务后续接入短时签名地址、限速与异常下载日志；官网只获取短时有效的下载地址。
